# Pixmint 产品扩展与收费落地规划

> 日期：2026-11-04
> 关联文档：`2026-11-04-architecture-audit.md`（架构体检）、`2026-11-04-monetization-and-plugin-plan.md`（市场调研与定价）
> 当前版本：0.7.0

## 一、先说一个结构性问题：17 个插件需要一扇"门"

你列的功能里，截图、查词、录屏、待办、文件搜索、格式转换……彼此没有调用关系。如果全部塞进设置页开关，用户装完软件后**根本不知道它们存在**，插件做了也没人用。

uTools 和 Raycast 的经验是：**先有一个唤起面板，再有插件**。

建议在 v0.8 就把"命令面板"作为核心壳的一部分（不是插件）：

```
Ctrl+Space（可改） → 弹出输入框
  ├─ 直接输入单词 → 查词（功能 1）
  ├─ 输入 >  → 列出所有命令/插件
  ├─ 输入 todo → 新建待办（功能 4）
  ├─ 输入 file xxx → 搜本地文件（功能 6）
  └─ 输入？ → AI 助手（功能 15）
```

面板是插件的统一入口，插件只要注册 `commands` 就能被搜到。设置页只负责**开关与配置**，不负责日常使用入口。

没有这一步，后面 17 个功能的投入产出会比预期低很多。

**关键结论：17 项里有 12 项天然跨平台，4 项需要平台特化实现，1 项（鼠标光标）在 macOS 上做不了。** 这意味着只要插件 manifest 的 `platforms` 字段做对、平台能力收在 Provider 里，**Mac 版主要是"核心壳"的移植，不是 17 个插件的移植**。反过来，如果现在让插件直接调 Windows API，未来就是 17 次返工。

### 逐项落地要点

**1. 查单词窗口**
- 复刻有道那种"输入即查"：输入框 + 音标（英/美）+ 发音按钮 + 词性分栏 + 例句。
- 数据源：内置 ECDICT（已有）；发音用 `Web Speech API`（OCR 弹窗已在用）；英美音标 ECDICT 已含。
- 关键体验：**全局快捷键唤起 → 输入 → 回车 → 可直接复制释义**，三步内完成。窗口失焦自动隐藏。
- 增强（Pro）：生词本一键添加、划词取词、词频统计。

**2. AI 单词本（艾宾浩斯）**
- 调度算法：SM-2 简化版即可，不必上 FSRS。间隔序列 1/2/4/7/15/30 天，答错回退一档。
- 数据模型：`word, source, addedAt, easiness, interval, dueAt, lapses, history[]`。
- UI 建议：首页一张"今日待复习 23"的卡片 → 进入复习流（看词回忆 → 翻面 → 认识/模糊/忘记）→ 结束页显示热力图与连续天数。
- 提醒：本地通知（Windows Toast），每天固定时间；**这是留存的关键，别省**。
- 存储：先 JSON（`vocab.json`），超过 5 千词再换 SQLite。

**3. 鼠标形状自定义**
- 技术路径：Windows `SetSystemCursor` + 自定义 `.cur`；需要在退出/崩溃/开机时恢复。
- 必须做：启动时先备份原始光标到 `cursors-backup/`，注册"下次启动若检测到未恢复则自动还原"。
- 建议直接用现成主题包（.cur 文件），不要做在线光标市场。

**4. AI 提醒**
- 待办/笔记/习惯三类，共用一条 `item` 表：`type, title, note, dueAt, repeat, doneAt`。
- "AI" 部分建议只做两件事：自然语言解析时间（"明天下午三点提醒我交周报"）和每日小结。别做过度承诺。
- 和单词本共用通知调度器，避免两套逻辑。

**5. 文件格式转换**
- 媒体类（视频/音频/图片）：ffmpeg，Electron 自带的是精简库，需单独打包 ffmpeg 二进制（约 30–70MB）。
- 文档类（docx/pdf/xlsx）：LibreOffice headless 太大。建议**首次使用时下载"转换组件包"**（按需下载，不随机分发）。
- 架构上这正好验证"插件可带独立资源"的能力。

**6. 搜索本地文件**
- 首选：检测是否安装 Everything，通过 `es.exe` 或 IPC 查询（毫秒级，零索引成本）。
- 兜底：Windows Search API（慢，但系统自带）。
- 不建议自建索引——那是另一个产品的工作量。
- 插件必须声明 `fs.read` + `process.exec` capability，这是权限体系的好样板。

**7. 磁盘清理**
- 只做"扫描 + 展示 + 用户逐项确认"，**永不做一键自动清理**。
- 安全类别：Temp、浏览器缓存、回收站、旧安装包、日志。
- 必须给出"预计释放"和"风险等级"，并默认不勾选高风险项。
- 建议推到很后面，或者干脆不做——一次误删就能毁掉口碑。

**8. 专业录屏（核心付费点）**
- 现有基础：`recording.ts` + `RecorderSession.ts`，MediaRecorder 30FPS。
- 要补的四件事，按性价比排序：
  1. **光标平滑 + 点击高亮**（录的时候记录鼠标轨迹，后期插值渲染）
  2. **自动缩放跟随**（根据点击密度自动推近/拉远，Screen Studio 的招牌）
  3. **背景/圆角/内边距**（导出时合成，最简单，视觉提升最大）
  4. **快捷键浮层**（监听全局按键并叠加）
- 技术选型：录制阶段采集"原始帧 + 鼠标/按键事件流"，后期在 Worker 里合成。不要指望 MediaRecorder 直接产出成品。
- 这条线会引入 ffmpeg 依赖，和功能 5 共用。

**9. 云端笔记**
- 不建议自建同步协议。优先方案：本地优先（Markdown 文件）+ 可选同步到用户自己的 WebDAV / 坚果云 / S3。
- 自建云要处理：账号、鉴权、配额、冲突、备份、注销。工期至少 3–4 周，且是长期运维负担。
- 如果一定要做，建议 v1.0 只做"单向备份 + 版本历史"，不做实时协同。

**10. 软件更新提醒**
- 已有 `electron-updater` + GitHub/generic 源。补：非打断式气泡、更新日志弹窗、可选"稍后"。
- 注意：**免费用户也必须能更新**，不要在更新通道上做付费拦截。

**11. 剪贴板预览**
- Electron 的 `clipboard` 没有变更事件，需要 300–500ms 轮询（轻量）或原生钩子。
- 支持文本/图片/链接/文件路径；图片存缩略图，原图可选。
- 隐私：默认排除 `KeePass/1Password/Bitwarden` 窗口标题；提供"暂停记录 1 小时"。

**12. 截图记录**
- 本地历史库：`history/index.json` + `thumbs/`，原图可选保存。
- 支持按 OCR 文本搜索（截图时顺手 OCR 存索引）——这是和普通历史记录拉开差距的点。
- 必须做容量上限与自动清理（默认 500 条 / 2GB）。

**13. 更新后动画介绍**
- 复用 `OnboardingApp.tsx` 的场景框架，新增 "What's New" 场景，读取 `CHANGELOG` 生成要点。
- 只在**大版本**（0.8→0.9）展示，补丁版本不要打扰。

**14. 分享链接**
- 对象存储建议 Cloudflare R2（无出网费）或腾讯云 COS。
- 流程：本地加密压缩 → 直传（预签名 URL）→ 返回短链 → 可设过期时间/密码/阅后即焚。
- 成本控制：免费用户不给，Pro 每月赠 1GB，超出用点数。

**15. AI 助手**
- 复用 `translation.ts` 的 provider 抽象，扩成通用 `LlmProvider`：OpenAI 兼容 / Anthropic / DeepSeek / Ollama。
- 形态建议：命令面板里的对话窗，支持"选中文字 → 解释/翻译/润色/总结"。
- 计费：**用户自带 Key 不收费**（降低心理门槛）；用你的额度按点数扣。

**16. 驱动电脑操作**
- 这是 Computer Use agent：截屏 → 模型决策 → 鼠标键盘动作 → 循环。
- 必须做：独立 `utilityProcess`、每步可见、危险操作二次确认、全局急停（Esc）、操作录像。
- 建议放在插件市场阶段，或者只作为"实验性功能"内置，不承诺稳定性。
- 不要和主程序强绑定——它出问题不能拖垮截图。

**17. 定时关机/开机**
- 关机/重启/睡眠：`shutdown /s /t` + 任务计划，简单。
- **定时开机**：需要主板 RTC 唤醒（BIOS 里开启），Windows 任务计划的"唤醒计算机"只在睡眠/休眠下有效。**没法制造成通用承诺**，必须在 UI 里明说"取决于硬件支持"。
- 杀软对"自动关机"类行为敏感，建议做成独立小工具插件，用户显式启用。

## 四、"下一个版本就收费"这件事，先看这张表

收费不是一个开关，是一串前置条件。任何一项缺失都会直接损失收入或引发退款：

| 前置条件 | 为什么必须有 | 状态 |
|---|---|---|
| 代码签名 | 无签名安装包被 SmartScreen 拦截，付费转化腰斩 | ❌ 未做 |
| 分发渠道决策（Mac） | 走 App Store 就必须用 Apple IAP，跨平台统一授权码方案作废；必须在写许可系统**之前**定 | ❌ 未决 |
| 至少 2 个硬付费功能 | 只有截图+OCR 卖不过 PixPin 免费版 | ❌ 未做 |
| 许可与试用 | 没有试用就没有转化；没有离线校验用户断网就不能用 | ❌ 未做 |
| 支付渠道与开票 | 用户付不了钱 / 要不到发票 | ❌ 未做 |
| 用户协议 + 隐私政策 + 退款条款 | 支付渠道审核要求，也是纠纷时的依据 | ❌ 未做 |
| 埋点 | 不知道谁在看价格页、谁卡在支付 | ❌ 未做 |
| 客服通道 | 授权失败、换机、退款全靠它 | ⚠️ 有反馈窗口，无人工流程 |

**建议**：如果坚持在 0.8.0 收费，就把"专业录屏 + 批量 OCR"塞进 0.8.0，工期会变成 10–12 周；否则先做 **0.8.0 早鸟预售**（¥99 预售 1.0 的 Pro），用预售验证需求，但要在页面上写清楚是预售、预计交付时间，避免口碑风险。

## 五、收费的技术实现

### 5.0 先做一个不可逆的决定：Mac 走 App Store 还是独立分发

这个决定会从根上改变授权系统，**必须在写第一行许可代码之前定下来**。

| | Mac App Store | 独立分发（DMG + 公证） |
|---|---|---|
| 分成 | Apple 抽 15%（小企业计划） | 0 |
| 支付 | 必须用 Apple IAP，禁止引导外部付款 | 自建（微信/支付宝/Paddle） |
| 自动更新 | 必须走 App Store 更新 | electron-updater 自管 |
| 沙箱限制 | 本地文件搜索只能访问用户选择的目录；磁盘清理基本做不了；插件下载与执行受限 | 无额外限制 |
| 审核 | 每次发版要审核，系统级权限功能容易被拒 | 无 |
| 成本 | $99/年 | $99/年（公证同样需要开发者账号） |
| 获客 | 有商店搜索流量 | 全靠自己 |

**建议：独立分发。** 你做的是一套要接管截图、录屏、剪贴板、本地文件、定时任务的"超级工具"，这些能力在 MAS 沙箱里几乎处处撞墙。未来如果想上架，单独做一个功能受限的 "Lite" 版，用 IAP 卖，不要期待同一个包两边通吃。

### 5.1 身份模型：先做授权码，后做账号

- **v0.8–0.9**：无账号。用户付款拿到授权码，本地激活，断网可用。
- **v1.0**：加可选账号，只服务于云功能（同步/分享/AI 额度）。**不登录也能用 Pro 本地功能**。
- **跨平台**：同一授权码 Windows / macOS 通用，3 台设备共享额度。这既是卖点（比"双平台分开卖"友好），也要求设备指纹两端格式统一。

理由：国内用户对"必须注册才能用"很敏感；授权码还能离线交付，适合数码荔枝这类渠道。

### 5.2 授权码格式

```
base64url(payload) + "." + base64url(ed25519_signature)
```

payload：
```json
{
  "v": 1,
  "kid": "2026-11",
  "plan": "pro",
  "order": "ord_8f3a...",
  "dev": "dev_2c91...",      // 首次激活时绑定，未激活为 null
  "iat": 1762300000,
  "exp": null,                // 终身卡为 null；订阅卡填到期时间
  "upd": "2027-11-04",        // 免费更新截止（大版本边界）
  "feat": ["record-pro","ocr-batch","clipboard-unlimited"]
}
```

- 公钥内置客户端，私钥只在服务端。客户端用 `@noble/ed25519`（纯 JS，无需原生编译）。
- 激活后服务端返回**设备绑定的 token**，本地用 `safeStorage` 加密存储。
- 未激活的原始授权码也可以离线验签（用于"先激活再联网"的场景）。

### 5.3 客户端模块

```
src/main/license/
  device-id.ts       Windows MachineGuid / macOS IOPlatformUUID + 用户名哈希，两端格式统一
  verify.ts          Ed25519 验签、payload 解析、有效期检查
  license-store.ts   safeStorage 加密存储 token 与激活时间
  refresh.ts         7 天刷新、30 天宽限、时钟回拨检测
  entitlements.ts    token → { plan, features:Set } 的唯一出口
```

门禁统一收口在一个函数：

```ts
requireEntitlement('record-pro')   // 在 IPC 注册器/插件注册表里调用
```

插件 manifest 的 `plan` 字段和这里共用同一份 `features` 列表，避免两套判断。

### 5.4 服务端

建议就用现有腾讯云东京服务器，Node + Fastify + SQLite（数据量小，别上 MySQL/Redis）：

| 接口 | 作用 |
|---|---|
| `POST /v1/activate` | 授权码 + 设备指纹 → 绑定设备，返回签名 token |
| `POST /v1/refresh` | token + 设备指纹 → 续签（7 天一次） |
| `POST /v1/deactivate` | 解绑设备（用户在网页上操作） |
| `POST /v1/trial` | 发放 7 天试用 token（设备/IP 限一次） |
| `POST /webhook/order` | 渠道支付回调 → 生成授权码 → 邮件 |
| `GET /v1/plans` | 价格表（客户端展示用，便于调价不用发版） |

表结构（4 张表够用）：`orders`、`licenses`、`devices`、`events`。

**可用性要求**：许可服务挂了不能影响用户使用——客户端宽限期 30 天，服务端健康检查 + 告警。

### 5.5 支付渠道（按落地成本排序）

| 顺序 | 渠道 | 为什么 | 工程成本 |
|---|---|---|---|
| 1 | **数码荔枝 / 少数派商店** | 有流量、能开票、支持批量发码；你只需导入授权码批次 | 低（发码 + 兑换页） |
| 2 | **爱发电** | 个人开发者零门槛，适合早鸟预售和赞助 | 低（webhook 发码） |
| 3 | **官网 + 微信/支付宝** | 利润最高，但个人无法直连，需个体户/公司资质 | 中（资质 + 对账） |
| 4 | **Paddle / Lemon Squeezy** | 出海，自动处理税务 | 中（海外主体或个人信息） |

**不建议**：个人用"易支付"类聚合通道收软件款——资金安全和合规风险都不划算，一旦被风控，已售用户的续费与售后会断。

### 5.6 试用与转化

1. 安装后不弹付费，先让用户用满 7 天。
2. 第 8 天起，在**使用付费功能时**弹一次"7 天全功能试用"，不打断。
3. 试用结束降级，数据保留，设置页显示剩余早鸟名额。
4. 每 14 天最多提醒一次，可永久关闭。

### 5.7 防破解：只做三件事

1. **服务端能力**：AI 额度、云同步、分享链接必须在服务端校验。
2. **更新通道**：可选地给 Pro 用户推送增强版安装包（但不要拦截免费用户的更新）。
3. **授权码黑名单**：退款/盗刷的码拉黑。

本地截图、录屏这些纯本地功能，一定会被 patch。把精力放在定价和服务上，比放在反破解上回报高得多。

## 八、三条容易踩的坑

1. **先做功能，后做底座** → 第 6 个插件开始每次改动都要全量回归，最终不敢发版。
2. **先收钱，后补体验** → 早期用户是口碑放大器，付费后遇到 bug 会放大负面。
3. **把所有功能做成"必须开会员"** → 免费版留不住人，付费转化率反而更低。免费版要能当主力。
4. **先写 Windows 专属逻辑再想着移植** → macOS 的截图、OCR、录屏是三套完全不同的 API。现在多花 3–5 天把平台能力收进 Provider，未来省 1–2 个月；反过来，等 17 个插件都写完再移植，就是 17 次返工。
