# 迭代回顾 2026-11-21 / v0.8.29（聚光灯遮罩修复：亮区标注蒙白纱 + 文字丢失）

## 结论

`conditional`

本轮修复聚光灯两处用户实测 bug：①亮区内的箭头/文字/序号像蒙了一层白纱；②聚光灯下文字换位置输入时上一段自动消失。根因分别是「主画布上盖全屏黑纱再挖洞，把亮区标注一起擦掉、靠半透明重描补救」和「文字提交依赖输入框失焦时序」。核心路径已由用户真机验证通过。

## 本轮变更

- `drawSpotlightMasks`：黑纱与挖洞全部在遮罩画布上完成（先铺 `rgba(0,0,0,0.55)` 全屏，`destination-out` 擦洞），再整张 `source-over` 叠到主画布。亮区完全透明，标注从未被擦掉。
- 删除 `plan.overlay` 重描层（`spotlight.ts` 的 SlackDrawPlan 去掉 overlay 字段）、`SPOTLIGHT_MASK_BORDER_ALPHA` 常量、无人引用的 `SlackDrawLayer` 类型。
- `handlePointerDown` 入口新增 `if (textDraft) commitText()`：文字草稿在新的按下到达时立即落盘，不再依赖 textarea blur 时序（聚光灯重绘会搅乱它）。
- 屏幕与导出两条绘制路径同步修改，顺序一致（非聚光灯标注 → 遮罩 → 聚光灯形状）。
- 更新 `redraw`/`drawSpotlightMasks` 顶部注释为新方案，防止后来者按旧注释理解。
- 新增回归测试文档 `docs/test-cases/P15-spotlight-mask-fix.md`（33 项手工用例）。
