# 功能：手动长截图

编号：P8 | 状态：Phase 1 核心实现完成；真实桌面传输待复测 | 版本：v2

## 需求描述

- 用户在截图覆盖层里框选一个固定区域。
- 用户自己滚动目标内容，工具连续采帧并拼接成一张长图。
- 不要求用户控制滚动速度，不要求每次停在固定位置。
- 滚轮、触控板、拖动滚动条都按同一套采集逻辑处理。
- HUD 显示已接屏数、当前高度和状态；检测到跳变时提示回滚，不静默输出残缺图。
- 支持暂停、继续、回退一屏、完成、取消；完成后进入预览，可保存 PNG、复制。
- 手动模式作为默认入口；自动滚动保留为可选模式。

## 非目标

- v1 不做浏览器 CDP 全页截图作为主路径；网页 CDP 作为后续增强。
- v1 不做 macOS / Linux，仅 Windows。
- v1 不做长图 OCR、长图钉图。
- 不承诺极端快速甩动也不丢内容；超过单帧物理重叠上限时提示回滚。
- 不新增用户可见的长截图参数设置，内部常量先固定。

## 用户场景

- 保存网页、聊天记录、文档、代码文件或设置页的完整内容。
- 目标应用不响应自动滚轮或 UIA，但用户自己可以滚动。
- 内容比当前窗口高几倍，需要一张连续长图而不是多张截图。

## 交互流程

```text
F1 进入覆盖层
      ↓
框选固定区域
      ↓
选择“手动滚动”（默认）
      ↓
3 秒倒计时，把鼠标放到选区内
      ↓
用户正常滚动
      ↓
工具连续采帧 → 逐帧匹配 → 追加新内容
      ↓
跳变：暂停追加，提示回滚；回退一屏可用
      ↓
完成 → 预览 → 保存 / 复制 / 关闭
```

## 技术方案

### 采集

- 目标 10–15fps 连续采帧，不再“停稳才截”。
- 帧格式使用原始 BGRA，不在每帧做 PNG/base64 往返；只在最后编码一次。
- 帧源抽象为独立模块，优先 GDI 原始帧；Electron `desktopCapturer` 视频流作为备选；Windows Graphics Capture 仅在数据证明前两者不足时引入。
- 手动模式只截固定屏幕区域，不找窗口句柄、不注入滚轮、不依赖 UIA。
- 采集时 HUD 和边框放在选区外，避免入镜。

### 匹配

- 每一帧都尝试和“上一张已接受帧”做重叠匹配。
- 使用预期偏移缩小搜索范围；置信度不足或接缝校验失败时不追加。
- 上一张已接受帧保持不变，用户回滚后可以继续接上。
- 动态遮罩滚动条、固定表头、固定底栏。
- 支持回退一屏，撤销最后一次追加的行。
- 可选读取 UIA `ScrollPattern` 的滚动百分比作为辅助信息，不作为前提。

### 拼接

- 增量拼接，只保留当前长图和必要的上一帧。
- 固定表头只出现一次；固定底栏按边界规则处理。
- 输出上限沿用 30,000px / 30,000,000 像素；超限提示分段或降采样。
- 完成时统一编码 PNG，避免逐帧编码拖慢采集。

### 速度边界

10fps、800px 视口、20% 重叠时，单帧最大位移约 640px，理论约 6400px/s；15fps 约 9600px/s。普通鼠标滚轮和触控板正常滚动在范围内，因此用户不需要感知速度。极端快速甩动超过物理上限时，提示回滚；这不是要求用户控速，而是任何像素采集方案都无法重建已跳过的内容。

## 性能预审

```text
成本模型：采集帧率 × 选区像素 × 每帧拷贝/匹配成本 → CPU/内存/延迟；输出尺寸 → 编码与保存成本。
基线 / 主导项：现有手动模式 250ms 采帧 + 停稳才拼；700×2934/9 屏约 15s；主导项是每帧 PNG/base64 往返和停稳等待。
杠杆 / 收益 / 风险：10–15fps + 原始帧 + 预期偏移搜索；收益是去掉停稳要求；风险是 4K 选区 CPU/内存和误匹配。
取舍 / 用户默认值：默认 10fps 自适应，大选区降帧或降采样；用户默认不控速，极端快滑提示回滚。
预算 / 待验证假设：700×600@10fps 是否可接受；4K 是否需要 WGC；30k px / 30M px 上限保留；需 spike 多次测量。
```

Phase 0 结果见 `docs/features/P8-capture-bench.md`。

## Phase 1 实现与验证（2026-10-27）

### 已实现

- `src/main/long-capture/frame-source.ts`：原始 BGRA 二进制帧源，24 字节帧头，PowerShell/C# sidecar。
- 手动循环改为 80ms 连续采帧，不再要求“停稳”或控制速度。
- 每帧都尝试匹配上一张已接受帧；失败保持上一张不动，回滚后可继续。
- 新增 `gap` 状态、反向滚动提示、回退一屏。
- 工具栏增加“手动长截图（推荐）”直接入口；自动长截图保留为第二个按钮。
- HUD 增加“需要回滚”和“回退一屏”。
- 自动模式中途丢失重叠时不再直接发布残缺图，而是进入错误状态并提供“改手动滚动”。

### 已验证

- `pnpm typecheck` 通过。
- `pnpm test` 通过：23 个文件、147 个用例。
- `pnpm build` 通过。
- 覆盖层 E2E 通过：工具栏宽度 847px，仍与选区右边缘对齐，新增按钮未破坏布局。
- 合成手动 smoke 通过：700×4134，`sawGap/sawUndo/sawPause=true`（高度随结束时机变化）。
- 合成原始帧传输 smoke 通过：700×600 9.20fps、1080p 9.06fps，p95 19/47ms，0 失败。
- Phase 0 GDI 数据：700×600 约 60fps，1080p 约 21fps，4K 合成区域约 15fps。

### 未验证

- 真实 GDI 采集 + 二进制传输：当前会话 `CopyFromScreen` 返回“句柄无效”，同一时刻直接 GDI 基准也失败，属于桌面会话状态；协议本身已用合成帧验证通过，需在未锁定桌面复测。
- 真实应用：Edge/Chrome、VS Code、微信/QQ、PDF、Excel。
- 真实 4K、125%/150%/200% DPI、多显示器。
- 动态滚动条、固定底栏、懒加载和动态内容。

## 已确认

- 用户于 2026-10-27 确认整体方案。
- 手动模式作为默认入口，自动模式保留为可选。
- 原生 WGC 仅在 spike 证明 GDI/Electron 不足时引入；本轮 spike 未触发。
- 30,000px / 30,000,000 像素上限沿用。
- 真实失败应用仍待用户提供，作为最终验收目标。

## 验收标准

- fixture 以 200–2000px/s 变速连续滚动，输出无缺失、无重复、无错位。
- 极端快速甩动时给出回滚提示，不能静默输出残缺图。
- 固定表头/底栏只出现一次；滚动条不污染匹配。
- 自动模式中途丢失重叠时，必须让用户选择继续/改手动/结束保留。
- 真实应用矩阵里，至少用户指定的失败应用通过；没有复现并通过，不标 `pass`。
- 性能沿用现有长截图预算；4K 允许降帧/降采样，但必须写明代价。
