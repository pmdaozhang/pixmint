# 功能：钉图文字选择与复制

编号：P14 | 状态：已实现 | 版本：v2

## 需求描述

用户截取一段较矮的文字区域并钉图后，会遇到两个问题：

1. 短选区被钉图窗口按最小高度拉伸，文字变形。
2. 钉图中的文字无法像图片查看器一样用鼠标选中，也无法复制。

目标行为：

- 短选区钉图后保持原图宽高比，不再纵向拉伸。
- 钉图创建后在后台识别图片文字，不阻塞窗口显示。
- 鼠标可在钉图文字上拖选，双击选词，支持 `Ctrl+A` 全选和 `Ctrl+C` 复制。
- 在文字以外的区域拖动仍移动钉图窗口；滚轮缩放、双击穿透、标注、复制图片和保存行为保持不变。
- 钉图标注并保存新图后，重新识别新图文字，旧文字层立即失效。

## 设计决策

- 位图本身不包含可选中文本，因此使用现有 PaddleOCR / Windows OCR 后端生成文字行坐标，在图片上方叠加透明文字层。
- 文字层只负责选择和剪贴板文本，不修改原图，也不影响复制图片、保存图片和标注合成。
- 钉图尺寸不再对宽高分别套最小值，而是用同一缩放比例计算；即使出现像素舍入，也优先保持宽高比。
- 图片继续使用透明阴影边距，但图片元素改用 `object-fit: contain`，作为尺寸计算的第二层防拉伸保护。
- OCR 异步执行，每张钉图只识别一次；识别失败时降级为普通钉图，不阻塞窗口，也不循环重试。
- 文字区域通过 `pointer-events` 和事件冒泡隔离，避免开始选择时触发窗口拖动。
- 文字层字号、位置和行框由 OCR 原图坐标换算到当前钉图显示尺寸；窗口滚轮缩放后通过 `ResizeObserver` 重新换算。
- 钉图窗口关闭或进入编辑模式时，渲染层取消旧 OCR 结果的应用；新图片完成后重新识别。
- 不新增依赖，复用现有 OCR 模型、队列和 IPC 安全边界。

## 验收标准

- [x] 300×14 一类的短选区钉图后，图片显示宽高比与原图一致，窗口高度不再被强制拉到 60px 以上。
- [x] 钉图创建后文字层在后台就绪；识别期间不阻塞图片显示、拖动和缩放。
- [x] 鼠标在文字上拖选可选中文字并显示高亮；双击可选中单词或词组。
- [x] `Ctrl+A` 全选当前钉图识别出的全部文字。
- [x] `Ctrl+C` 把选中文字写入系统剪贴板，不覆盖用户未选中文字时的图片复制入口。
- [x] 在文字以外的区域拖动可移动钉图窗口。
- [x] 滚轮缩放后文字层与图片保持对齐。
- [x] 进入标注编辑时隐藏文字层，完成编辑后对新图重新识别。
- [x] OCR 失败或识别不到文字时，钉图仍可复制、保存、关闭和标注。
- [x] 原有钉图 E2E、覆盖层 E2E、OCR 测试和构建通过。
- [x] OCR 100 次压测 3 轮均低于 128MB RSS 预算，p95 低于 250ms。

## 资源生命周期

| 资源 | 创建者 | 持有者 | 释放点 | 失败兜底 |
|---|---|---|---|---|
| 钉图窗口 | `PinManager.create` | `PinManager.pins` | 窗口关闭 / `destroyAll` | 创建失败由主进程错误路径报告 |
| 钉图图片字节 | 覆盖层导出 | `PinState` | 钉图窗口关闭 | 图片为空时不创建钉图 |
| OCR 任务 | 钉图渲染层 | OCR 队列 | 任务完成 / 窗口关闭后结果丢弃 | 失败只降级为普通钉图，不重试 |
| 文字层 DOM | `PinApp` | React | 图片变化、进入编辑、组件卸载 | 识别结果为空时不渲染文字层 |
| 图片 Blob URL | `PinApp` | React 状态 | `imageUrl` 变化或卸载 | 创建失败时保持普通钉图 |

约束：

- OCR 复用现有串行队列，避免多张钉图并发启动 PowerShell 或 ONNX 推理。
- 不对单张钉图自动重试 OCR，避免持续占用 CPU。
- 首次 OCR 的模型加载成本只发生一次；后续钉图复用已加载模型。
