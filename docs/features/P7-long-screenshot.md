# 功能：长截图

编号：P7 | 状态：设计中（方案已确认） | 版本：v2

## 需求描述

- 在截图覆盖层的工具栏增加“长截图”入口。
- 用户框选一个可滚动区域后，应用自动滚动目标窗口，逐帧截图并按重叠拼接成一张长图。
- 滚动过程中显示已截取屏数、当前高度和状态，支持暂停、继续、完成和取消。
- 完成后打开长图预览，支持缩放查看、保存和复制。
- 固定表头、固定底栏、滚动条、光标和动态内容不能造成明显重复、缺失或错位。
- 达到高度或内存上限时停止并保留已截取部分，明确提示用户。
- 目标窗口不可滚动、失去焦点、是 UAC/受保护窗口或滚动未生效时，给出可操作的中文错误。

## 用户场景

- 保存网页、聊天记录、文档、代码文件或设置页的完整内容。
- 保存比当前窗口高几倍、但无法一次性截全的内容。
- 需要把长内容发给别人，而不是发多张分散的截图。

## 非目标

- 不做 macOS / Linux 长截图，首版仅 Windows。
- 不做浏览器 DevTools Protocol 全页截图，通用滚动拼接优先。
- 不做自动识别“页面是否已经到底”的语义判断，只基于像素变化和滚动结果。
- 不在 v1 做长图钉图，超长图片钉在桌面上没有实际意义。
- 不在 v1 做长图 OCR，先保证采集、拼接、预览、保存可靠。
- 不新增用户可见的长截图参数设置，内部常量先固定。

## 已确认（2026-10-27）

- 不做浏览器 CDP 全页截图，v1 统一走滚动拼接。
- 接受从当前滚动位置向下截取，不强制回到顶部。
- 最大 30M 像素 / 30,000px 高度上限合适。
- v1 只做保存/复制，不做长图 OCR 和钉图。
- 代码基线使用本地最新提交 `0ab0553`（0.4.1）。注意：`origin/feat/stability-foundation` 仍在 `1723a57`，本地领先 4 个提交，0.4.1 尚未推送。
- 功能版本按 semver minor 使用 0.5.0；如果要求版本号保持 0.4.1，需要在实施前单独确认。

## 交互流程

```text
按 F1 进入截图覆盖层
      ↓
框选可滚动区域
      ↓
点工具栏“长截图”
      ↓
识别选区下的目标窗口，隐藏覆盖层
      ↓
截第 1 帧
      ↓
发送滚轮，等待稳定，截第 2 帧
      ↓
计算相邻帧重叠，裁掉重复部分并拼接
      ↓
重复，直到到底 / 达到上限 / 用户停止
      ↓
打开长图预览
      ↓
保存 / 复制 / 关闭
```

## 技术原理

长截图不是单次截图 API，而是“滚动驱动 + 多帧采集 + 重叠匹配 + 增量拼接”的流水线。

1. 选区确定后，找到选区中心下的目标窗口句柄。
2. 隐藏覆盖层，避免工具栏和遮罩进入截图。
3. 使用 `fastCapture.capture(physicalRect)` 截取选区矩形。
4. 把鼠标移到选区中心，向目标窗口发送滚轮事件。
5. 等待画面稳定后截下一帧。
6. 用上一帧底部条带在下一帧中搜索，得到实际滚动偏移和重叠高度。
7. 只保留下一帧中不重叠的新内容，追加到长图缓冲区。
8. 连续多次没有新增内容、达到最大高度或用户停止时结束。
9. 编码为 PNG，写入临时文件，打开预览窗口。

核心难点不是拼接，而是：

- 不同应用的滚动步长不同，不能假设固定像素。
- 固定表头/底栏会在每一帧重复出现。
- 光标、动画、视频、输入框闪烁会干扰匹配。
- 受保护窗口、UAC 窗口、全屏游戏可能无法自动滚动或截图。
- 长图原始像素很大，必须增量拼接并限制最大尺寸。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-01 | 覆盖层工具栏增加图标按钮“长截图”，仅截图模式显示，钉图编辑模式不显示。 |
| FR-02 | 选区最小 120×120；选区中心必须落在可见窗口上，否则提示“请选择一个可滚动窗口”。 |
| FR-03 | 首帧使用当前选区原始画面，不包含标注和覆盖层。 |
| FR-04 | 滚动由 Windows helper 执行：`SetForegroundWindow` + `SetCursorPos` + `SendInput` 滚轮；结束后恢复用户鼠标位置。 |
| FR-05 | 滚动步长自适应，目标为选区高度的 65% 到 75%；首次保守滚动，后续根据实测偏移调整。 |
| FR-06 | 每次滚动后等待 120–200ms 再截帧；若连续两帧完全一致，最多重试 3 次。 |
| FR-07 | 重叠匹配使用灰度降采样 + 底部条带模板匹配 + 逐行校验；置信度低于阈值时停止并提示。 |
| FR-08 | 固定表头/底栏在多帧中不变时只保留一次；v1 先检测顶部固定区域，底部固定区域作为边界场景。 |
| FR-09 | 增量拼接，只保留最终缓冲区和当前帧；最大输出 30,000,000 像素或 30,000px 高度，先到者为准。 |
| FR-10 | 进度 HUD 不覆盖选区，显示已截屏数、当前高度、状态；支持暂停、继续、完成、取消。 |
| FR-11 | 完成或手动“完成”后打开长图预览，支持缩放/滚动查看、保存、复制。 |
| FR-12 | 取消丢弃本次结果；达到上限时保留已截部分并提示“已截取到上限”。 |
| FR-13 | 目标窗口失去焦点、滚动无变化、UAC/受保护窗口、内存不足时停止并保留已截部分。 |
| FR-14 | 更新诊断日志：窗口类名、句柄、滚动次数、实际偏移、匹配置信度、帧数、输出尺寸；不记录完整窗口标题。 |
| FR-15 | 进度 HUD 不抢焦点；Esc 取消；减少动效下不播放过渡动画。 |

## 设计决策

- v1 只做 Windows，复用现有 `fastCapture` 和 `SidecarClient`，不引入 `robotjs` / `nut.js` 等原生 npm 依赖。
- 滚动 helper 使用常驻 PowerShell + `Add-Type` C#，与 `window-snap` / `fast-capture` 保持同一套 sidecar 机制。
- 匹配和拼接纯逻辑放在 `src/shared/long-capture.ts`，主进程只负责采集、滚动和状态机，便于单测。
- 使用 Electron `nativeImage` 解码/编码和 BGRA Buffer 拼接，避免把 `fast-png` 从 devDependency 提升为运行时依赖；若 `nativeImage` 在 20,000px 以上不稳定，再回退到 `fast-png` 并调整依赖分类。
- 增量拼接，不保留全部帧；只保留当前长图缓冲区和最后一帧。
- 目标窗口从选区中心识别，不要求用户先点窗口；选区可以落在嵌套滚动容器内，滚轮事件会作用于指针下的控件。
- v1 从当前滚动位置向下截取，不强制滚到顶部；后续可增加“从头开始”。
- 完成结果写入临时 PNG 文件，通过 `snapglass-media` 协议给预览窗口读取；关闭预览或退出时清理。
- 长图预览使用独立窗口，不复用录制预览，避免视频/ GIF 状态混入。
- 不修改设置 schema，不新增持久化字段。

## 性能与取舍预审

```text
成本模型：每帧采集 50–120ms，匹配 5–20ms，拼接 10–30ms，最终 PNG 编码 1–3s（20k px 参考值）。总时间由“帧数 × 滚动等待”主导。
基线 / 主导项：当前 F1 到覆盖层 p95 250ms；长截图没有基线。滚动等待和逐帧采集是主导项，匹配和拼接不是。
杠杆 / 收益 / 风险：只截选区、匹配降采样、增量拼接、限制帧数和像素上限、nativeImage 编码。风险是滚动兼容性、固定表头和动态内容。
取舍 / 用户默认值：v1 自动滚动 + 暂停/取消；最大 30M 像素；PNG 输出；不做 OCR/钉图。
预算 / 待验证假设：10 屏 < 20s；20k px 编码 < 10s；额外内存 < 256MB；假设 SendInput 在目标应用可用。
```

## 验收标准

- [ ] 覆盖层工具栏出现“长截图”入口，点击后进入长截图流程。
- [ ] 5 屏测试页输出高度大于视口，行号 1..N 不缺失、不重复。
- [ ] 固定表头只出现一次。
- [ ] 图片、代码块、深浅色页面拼接处无明显错位。
- [ ] 进度 HUD 显示已截屏数和高度，暂停/继续/完成/取消可用。
- [ ] 取消不产生结果文件；完成或达到上限时保留已截部分。
- [ ] 125% / 150% / 200% DPI 下偏移和拼接正确。
- [ ] 多显示器、跨屏选区、窗口移动时有明确结果或错误提示。
- [ ] 目标窗口不可滚动、失焦、UAC/受保护、滚动无变化时停止并提示。
- [ ] 最大高度/像素上限触发时停止，提示“已截取到上限”。
- [ ] 预览窗口可缩放/滚动，保存和复制结果正确。
- [ ] 临时文件在关闭预览、取消和退出后清理。
- [ ] 现有截图、标注、OCR、翻译、GIF/视频录制回归通过。
- [ ] 无新增设置 schema 变更，无新增未评估运行时依赖。

## 风险

- 部分应用只认真实硬件滚轮，`SendInput` 仍可能被忽略。
- 固定表头/底栏和嵌套滚动容器会增加匹配复杂度。
- 动态内容（视频、轮播、输入框光标）会造成误判，需要稳定帧重试。
- UAC、DRM、受保护内容无法截图或自动滚动。
- 长图 PNG 体积可能很大，保存和传输成本高。
- PowerShell helper 首次启动有编译延迟，需要预热。
- 工具栏按钮增加后可能挤压现有按钮，需要在 860px 最小宽度下验证。
- `nativeImage` 在超大尺寸上的上限需要 spike 验证。
