# 功能：窗口长截图

编号：P8 | 状态：已实现，待真实用户页面验收 | 版本：v1

## 需求描述

- 截图工具栏新增窗口长截图入口，入口只显示图标，不显示“长截图”文字。
- 点击入口后展示真实桌面窗口列表，按屏幕和窗口分组。
- 用户选中窗口后，先在该窗口真实内容上显示默认内容区选区。
- 默认选区覆盖窗口主滚动内容区，允许拖动四角或四边微调，不能越出内容区。
- 确认后自动向目标窗口发送滚动事件，连续采帧并拼接成长图。
- 长图生成后打开独立预览窗口，支持保存、复制和关闭。
- 提供暂停、继续、回退一屏、完成、取消和重试。
- 支持从确认页“重新选择”返回窗口列表，不丢失桌面冻结状态。
- 目标窗口没有可滚动内容、关闭、句柄变化或辅助进程失败时，给出可读错误。

## 非目标

- 本次不实现 macOS 窗口 UIA 采集。
- 本次不允许直接选择“整个屏幕”开始，屏幕项保留为说明，必须选择具体窗口。
- 不保证所有自绘、游戏、视频、地图、虚拟列表或禁用滚轮的应用都能自动滚动。
- 不做浏览器 CDP、应用专用导出协议或云端拼接。
- 不修改现有手动长截图入口和自动长截图算法。

## 交互流程

1. F1 进入截图覆盖层，框选任意区域，工具栏出现窗口长截图图标。
2. 点击图标，工具栏旁打开窗口选择器。
3. 选择具体窗口，主进程激活目标窗口并读取窗口、客户区和滚动内容区。
4. 冻结截图和选择器隐藏，目标显示器显示透明选区层。
5. 用户确认或微调内容区，点击“开始长截图”。
6. 选区层隐藏，HUD 与四边边界显示；自动滚动、采帧、匹配、拼接。
7. 完成后打开长图预览；关闭预览时清理临时结果。

## 设计决策

- 窗口枚举使用 `desktopCapturer`，窗口内容区使用 PowerShell + UI Automation。
- 选择器放在截图覆盖层内，避免再引入一个独立全屏窗口。
- 实时选区层只画边框、遮罩、手柄和确认卡，不覆盖目标窗口内容。
- 自动滚动前校验滚动目标 `hwnd` 与用户选择窗口一致，避免 z-order 变化时滚错窗口。
- 选区边界和八向缩放抽成 `src/shared/window-selection.ts` 纯函数，单测覆盖。
- 选择器过滤 Pixmint 自身、设置窗和长截图辅助窗口。
- 屏幕项保留但禁用，避免用户点击后才发现无法识别具体窗口。
- 窗口选择 PowerShell 协议与 `SidecarClient` 统一为 `id,command,...` 请求和 `id|payload` 响应。

## 关键约束

- 窗口内容区坐标统一为显示器相对 DIP；屏幕物理坐标只在主进程换算。
- 最小选区为 `120 × 120`；目标内容区小于该值时使用内容区实际尺寸。
- 自动滚动必须在选区外显示 HUD，HUD 和边界不能进入长图。
- 取消、重选、目标关闭和窗口句柄变化都必须清理选区层与旧目标。
- 选择器异步读取窗口列表，加载、空列表和错误状态都必须有可见反馈。

## 实测结果（2026-10-27）

- `pnpm typecheck`：通过。
- `pnpm test`：23 个测试文件、147 个用例通过。
- `pnpm build`：main、preload、renderer 全部通过。
- `node scripts/spike/verify-window-long-capture-demo.cjs`：Demo 的窗口选择、缩放、自动滚动、暂停、预览、错误态和浅色主题全部通过。
- `node e2e-overlay.cjs`：既有覆盖层 E2E 通过。
- `pnpm e2e:window-long`：真实 Edge 窗口通过纯图标入口、窗口选择、选区确认、重新选择、至少自动滚动 2 屏，最终生成 884×1283 预览。
- 实测发现并修复两处窗口目标辅助进程缺陷：Sidecar 协议不匹配、`GetCurrentThreadId` 错声明在 `user32.dll`。

## 风险

- UI Automation 对不同应用暴露的滚动内容区差异较大；无法暴露时只能报错，不会伪造结果。
- 前置固定栏、侧栏、虚拟列表和一次滚动超过整屏的应用仍可能导致重叠不足。
- 自动滚动依赖前台窗口和真实交互桌面；锁屏、远程桌面最小化或 UAC 安全桌面不可用。
- 透明全屏选区层在部分显卡驱动上可能带来合成开销，需继续观察真实长跑。
