# 测试用例：稳定性与跨平台基础（对应功能 P4）

版本：v1 | 上次更新：2026-10-22

## 正常场景

| 用例 | 步骤 | 预期 |
|---|---|---|
| TC-001 | 启动应用，完成一次截图并复制 | 应用正常；诊断日志有启动、截图开始、截图完成和 action 面包屑 |
| TC-002 | 打开设置页 | 诊断卡片显示日志路径、崩溃报告数量和兼容模式状态 |
| TC-003 | 点击“打开目录” | 系统文件管理器打开日志目录 |
| TC-004 | 点击“立即写入日志” | 当前队列同步落盘，提示成功 |
| TC-005 | 正常退出应用 | 停止资源采样并同步 flush 日志，无残留定时器 |

## 边界场景

| 用例 | 步骤 | 预期 |
|---|---|---|
| TC-101 | 连续写入超过 100 条面包屑 | 只保留最近 100 条，最早的被丢弃 |
| TC-102 | 日志超过 2MB | 轮转为 `.1.log`，最多保留 3 个文件 |
| TC-103 | 设置包含未知字段或非法枚举 | 未知字段被丢弃，非法值回退默认值 |
| TC-104 | 旧版本设置缺少 `schemaVersion` | 自动补为 1，其余合法字段保留 |
| TC-105 | 诊断日志包含 Windows 用户名、macOS 用户目录或 Bearer Token | 落盘前替换为 `<user>` / `<redacted>` |
| TC-106 | sidecar 响应被拆成多个 chunk | 行缓冲拼接后再解析，不丢请求 |
| TC-107 | sidecar 返回非法 ID 或缺少分隔符 | 忽略该行，不影响其他请求 |
| TC-108 | 在未接入的平台启动并触发截图/OCR | 应用可启动，调用真实能力时给出明确的“平台未接入”错误 |
| TC-109 | 运行 `pnpm soak:overlay` | 生成 `test-results/overlay-*.json`，包含失败、p95、内存和临时文件 |
| TC-110 | 运行 `pnpm soak:ocr` | 生成 `test-results/ocr-*.json`，失败数为 0 时退出码为 0 |
| TC-111 | 运行 `pnpm soak:recording` | 生成 `test-results/recording-*.json`，超过 1MB 的临时残留会使脚本失败 |
| TC-112 | 设置页点击“导出报告”并选择路径 | 生成可读 JSON，包含日志尾部、最近崩溃、指标、面包屑；不包含截图/OCR 文字/密钥 |
| TC-113 | 推送分支或创建 PR | GitHub Actions 在 Windows 上跑 typecheck、81 个单元测试和构建，全部通过 |

## 异常场景

| 用例 | 步骤 | 预期 |
|---|---|---|
| TC-201 | 人为制造主进程未捕获异常 | 生成崩溃 JSON，flush 日志，应用退出 |
| TC-202 | 人为制造未处理 Promise rejection | 生成崩溃 JSON，应用继续运行 |
| TC-203 | 强制结束设置页渲染进程 | 生成 `render-process-gone` 报告，主进程不崩溃 |
| TC-204 | 设置文件写入半截后强制退出 | 原始设置文件不被半截内容覆盖，临时文件不残留 |
| TC-205 | 设置文件损坏 | 生成 `.corrupt-` 备份，应用使用默认设置启动 |
| TC-206 | 崩溃报告超过 20 份 | 只保留最近 20 份 |
| TC-207 | sidecar 请求超时 | 返回 null，重启 helper，旧请求不悬挂 |
| TC-208 | sidecar 请求被新请求取代 | 旧请求立即返回 null，新请求正常响应 |
| TC-209 | 应用退出时 sidecar 仍在运行 | dispose 终止进程并清理临时脚本 |
| TC-210 | 旧 sidecar 进程延迟退出，此时已有新请求 | 旧退出事件不取消新请求，新请求仍能正常返回 |
| TC-211 | 连续触发两次 OCR | 两个任务串行执行，临时脚本不互相覆盖并会被清理 |
| TC-212 | 翻译接口长时间不返回 | 15 秒后中止并提示翻译超时，不无限挂起 |
| TC-213 | 渲染层尝试打开外部链接或新窗口 | 导航被阻止，不创建新窗口 |
| TC-214 | 外部来源请求 media/display-capture 权限 | 权限被拒绝；受信任应用页面仍可请求 |
| TC-215 | 设置 `PIXMINT_USER_DATA_DIR` 后启动应用 | 日志、设置和缓存写入指定目录，不写 AppData |
| TC-216 | 在原生 Windows 会话运行 `pnpm smoke` | 输出 `SMOKE_OK`，退出码 0 |
| TC-217 | 运行设置页 E2E | 启动、主题、密钥加密/清除通过 |
| TC-218 | 运行覆盖层 E2E | 框选、工具条、标注、复制、watchdog 全部通过 |
| TC-219 | 运行覆盖层 200 次压测 | 0 失败，p95 在预算内；记录内存变化 |
| TC-220 | 桌面捕获权限不可用 | 5 秒内报错并返回，覆盖层隐藏，不挂死应用 |
| TC-221 | 正常启动源码版并打开设置窗口 | 出现可见的 Pixmint 设置窗口，主进程保持响应 |
| TC-222 | 正常启动后执行 `--capture-once` | 走真实 `startCapture`；捕获不可用时输出 `CAPTURE_KIND fallback` 并在超时后返回 |
| TC-223 | 覆盖层连续开关 100 次 | JS 堆和 DOM 节点稳定；工作集增长不超过预算，记录在压测报告 |
| TC-224 | 运行真实截图压测 300 次 | 0 失败；报告包含 p95、renderer working/private bytes 和内存趋势 |
| TC-225 | 设置 `PIXMINT_SOAK_RECORD_SECONDS=590` 运行录制压测 | 3 次录制完成，0 失败，无超过 1MB 的临时残留 |
| TC-226 | 截图后按 Esc，重复 50 次 | 0 失败；renderer private 增长 ≤ 32MB |
| TC-227 | 截图后点复制，重复 50 次 | 0 失败；renderer private 增长 ≤ 64MB（含系统剪贴板占用） |
| TC-228 | 截图后钉图并关闭钉图，重复 50 次 | 0 失败；renderer private 增长 ≤ 32MB |
| TC-229 | 截图后 OCR 并关闭结果窗，重复 50 次 | 0 失败；renderer private 增长 ≤ 32MB |
| TC-230 | 截图后保存并删除文件，重复 50 次 | 0 失败；renderer private 增长 ≤ 48MB（含文件写入缓冲） |
| TC-231 | 3×590 秒录制结束后空闲 60 秒 | Tab private 增长 ≤ 64MB，临时残留为 0 |
| TC-232 | 系统缩放 150%，运行覆盖层 E2E | VIEWPORT 1280×720，框选/工具栏/文字/缩放/复制/watchdog/大选区全部通过 |
| TC-233 | 系统缩放 200%，运行覆盖层 E2E | 当前显示器不提供 200%，无法执行；换支持 200% 的机器后补测 |

## 回归范围

改这个功能时，以下功能不能坏：

- F1 截图、框选、标注、复制、保存、贴图
- OCR 识别与翻译
- GIF 和视频录制
- 设置页读取/保存快捷键、主题、语言、翻译配置
- 单实例锁与托盘常驻
