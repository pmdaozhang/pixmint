# 测试用例：应用内更新（对应功能 P6）

版本：v2 | 上次更新：2026-10-26

## 正常场景

| 用例 | 步骤 | 预期 |
|---|---|---|
| TC-001 | 开发模式执行 `pnpm dev` | 不发起更新请求，日志无 updater 检查记录 |
| TC-002 | 打开设置窗口 | “关于与更新”卡片位于“外观与启动”和“诊断”之间，显示 `Pixmint v0.4.0` |
| TC-003 | 更新源返回同版本，点“检查更新” | 显示“已是最新版本”，按钮恢复为“再次检查” |
| TC-004 | 本地 generic 源返回 0.4.1，点“检查更新” | 显示“发现新版本 0.4.1”和“下载更新” |
| TC-005 | 点“下载更新” | 进度条从 0% 增长到 100%，显示已下载 / 总大小，窗口不卡顿 |
| TC-006 | 下载完成 | 进入校验状态，校验通过后显示“重启并安装” |
| TC-007 | 点“重启并安装” | 应用退出，NSIS 静默安装，重启后版本为 0.4.1 |
| TC-008 | 更新完成后打开设置 | 主题、快捷键、翻译配置、密钥状态保留 |
| TC-009 | 打包版启动后等待 15 秒 | 日志出现一次检查记录；设置页状态同步更新 |
| TC-010 | 0.3.10 手动运行 0.4.0 安装包 | 覆盖安装成功，用户数据和缓存保留 |
| TC-011 | 0.4.0 从本地源更新到 0.4.1 | 完整链路通过，更新后截图、OCR、录制仍可用 |
| TC-012 | 执行 `pnpm build` 和打包 | `release` 生成 `latest.yml`、`.blockmap`、`Pixmint-Setup-0.4.0.exe`，文件名一致 |
| TC-013 | 连续点两次“检查更新” | 第二次被忽略或复用当前检查，不产生并发请求 |
| TC-014 | 下载中关闭设置窗口，再重新打开 | 下载继续，重新打开后进度恢复显示 |
| TC-015 | 下载完成后再次点“检查更新” | 在安装前保持 `downloaded` 状态，不重复下载 |
| TC-016 | GitHub 仓库 0 个 Release，点“检查更新” | 显示绿色“已是最新版本”，备注“更新源暂无发布记录”，按钮为“再次检查” |

## 边界场景

| 用例 | 步骤 | 预期 |
|---|---|---|
| TC-101 | 更新源响应超过 15 秒 | 显示“检查更新失败”，按钮恢复，可重试 |
| TC-102 | 更新源返回 404 | 显示“更新源不可用，请稍后重试” |
| TC-103 | 下载到 40% 时断开网络 | 显示“下载中断”，保留已下载进度或允许重新下载 |
| TC-104 | 篡改安装包使 SHA-512 不匹配 | 显示“安装包校验失败，已阻止安装”，不进入安装 |
| TC-105 | 安装目录被占用或安装器失败 | 显示“安装失败，请手动下载最新版本”，原版本仍可启动 |
| TC-106 | 下载中退出应用 | 进程正常退出，临时文件不残留超过预算，重新启动后可重新下载 |
| TC-107 | 磁盘剩余空间不足 | 显示下载失败和可读原因，不产生损坏的安装包 |
| TC-108 | 更新源版本低于当前版本 | 不提示降级，显示“已是最新版本” |
| TC-109 | 更新源版本号格式非法 | 检查失败并写入诊断日志，不崩溃 |
| TC-110 | 用户在下载中切到浅色 / 深色主题 | 进度条和状态颜色正确切换，无布局跳动 |

## 异常场景

| 用例 | 步骤 | 预期 |
|---|---|---|
| TC-201 | 完全断网后点检查 | 显示网络错误文案，可重试，应用不崩溃 |
| TC-202 | GitHub API 限流 | 显示检查失败，不阻塞其他功能 |
| TC-203 | 未签名安装包触发 SmartScreen | 记录为已知风险；用户确认后仍可完成安装 |
| TC-204 | 安装完成后首次启动崩溃 | 现有兼容模式生效，诊断日志包含上次版本和更新记录 |
| TC-205 | 更新器初始化失败 | 设置页显示“更新不可用”，截图和 OCR 不受影响 |

## 回归范围

- 应用启动、单实例锁、托盘菜单、设置窗口显示与关闭
- 截图、标注、复制、保存、钉图
- OCR、翻译、翻译方向选择
- GIF / 视频录制、预览、保存
- 设置读写、密钥存储、诊断日志、崩溃报告
- 安装包覆盖安装、用户数据保留
- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm package`
